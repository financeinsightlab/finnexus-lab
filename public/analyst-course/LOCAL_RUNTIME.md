# SignalPath Local Runtime

SignalPath is designed to run without a cloud account or external API.

## Actual local SQL execution

The SQL Practice Lab can now run read-only SQL against the local SaaS CSV dataset through Python's built-in SQLite library.

```bash
python3 local_sql_server.py
```

Then open the platform through the server preview on port **8001** and use **SQL Lab → Execute locally**.

The server:
- serves the whole workspace locally;
- creates an in-memory SQLite database from the SaaS CSV files for every query;
- exposes only `POST /api/sql`;
- accepts only one `SELECT`, `WITH`, or `EXPLAIN` statement;
- blocks write/database-administration commands;
- limits returned rows to 200;
- makes no outbound request and stores no SQL query history.

## Actual local Python execution

The Python Lab also uses the same local server at `POST /api/python`.

- It preloads `customers` and `transactions` Pandas DataFrames.
- Learners can run a scoped Python cell and assign a DataFrame or Series to `result` for a real table preview.
- It permits only Pandas, NumPy, Matplotlib and Seaborn imports.
- It blocks file, dynamic-execution, reflection and system-oriented functions.
- It is designed as a local learning environment, not a hardened multi-user security sandbox; run only your own learning code.

## Actual local spreadsheet validation

The Spreadsheet Lab can upload a learner `.xlsx` workbook to `POST /api/spreadsheet` on the same local server.

The file is read in memory and is not stored. The local validator checks:
- required `raw_orders`, `clean_orders`, `analysis`, `dashboard`, and `cleaning_log` worksheets;
- raw-data presence;
- formula evidence;
- SUMIFS/SUMIF evidence;
- gross-profit and gross-margin formula signals;
- sample formulas and focused improvement feedback.

It is evidence validation, not a replacement for human review of business definitions or dashboard usability.
